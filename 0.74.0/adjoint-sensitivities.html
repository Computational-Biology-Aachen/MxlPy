    Adjoint gradients¶

    Forward sensitivities give the derivative of every simulated value with respect to every parameter. Gradient-based fitting usually needs much less: the gradient of one number, the loss, with respect to all parameters. For a loss \(L\) that depends on the simulation at a few time points, that gradient is a vector-Jacobian product

    \[\frac{dL}{d\theta} = \sum_i \frac{\partial L}{\partial y(t_i)} \frac{\partial y(t_i)}{\partial \theta} = \sum_i w_i^\top S(t_i)\]

    with the cotangents \(w_i = \partial L / \partial y(t_i)\).

    Forward sensitivities compute all of \(S\), integrating \(n\) extra states per parameter. The adjoint method computes the product directly: it integrates an adjoint state \(\lambda\) backwards in time,

    \[\frac{d\lambda}{dt} = -\left(\frac{\partial f}{\partial x}\right)^{\!\top} \lambda, \qquad \lambda \mathrel{+}= w_i \text{ at every } t_i, \qquad \frac{dL}{d\theta} = \int_0^T \lambda^\top \frac{\partial f}{\partial \theta}\, dt + \lambda(0)^\top \frac{\partial x_0}{\partial \theta}.\]

    That is one forward and one backward solve, however many parameters there are. This is what makes fits with hundreds of parameters practical, e.g. the weights of neural networks in hybrid models.

    cost per gradient best for
    finite differences \(2m\) simulations models that can't be differentiated
    forward sensitivities one solve with \(n(1 + m)\) states few parameters, residual Jacobians (least squares)
    adjoint one forward and one backward solve with \(n\) states many parameters, loss gradients

    Both products \(\lambda^\top \partial f / \partial x\) and \(\lambda^\top \partial f / \partial \theta\) are generated symbolically in reverse mode, without forming Jacobians. The backward solve interpolates the forward trajectory instead of integrating the model backwards, which would be unstable for stiff models.

    adjoint_sensitivities.time_course returns an AdjointSensitivities object with

    • gradient: the derivative of sum(cotangents * y) with respect to every name in wrt (parameters, and variables for their initial values)
    • simulated: the simulated values at the cotangents' time points and columns
    • method: "adjoint", "forward" or "finite_difference"
    • adjoint: the adjoint state \(\lambda(t)\); \(\lambda(0)\) is the gradient with respect to the initial values

    Steady states¶

    Protocols¶

    protocol_time_course differentiates a protocol simulation, whose steps set parameters. The adjoint runs backwards through the steps with each step's parameters; \(\lambda\) is continuous at the step ends. Forward sensitivities don't support protocols, so the alternative is finite differences, and auto uses adjoints from PROTOCOL_ADJOINT_THRESHOLD (3) parameters on.

    Loss gradients in fits¶

    Fits get their derivatives from the runner. With derivatives="adjoint" the gradient of the loss comes from one adjoint solve, with the cotangents \(\partial L / \partial y\) of the chosen loss (standard scaling, replicates, GaussianNll weights and priors included). Residual Jacobians, which least-squares methods need, can't come from adjoints cheaply and still use forward sensitivities.

    When adjoints pay off¶

    Forward sensitivities integrate \(n(1 + m)\) states with dense Jacobians of that size, adjoints cost about the same for any number of parameters \(m\). method="auto" therefore switches to adjoints from adjoint_sensitivities.ADJOINT_THRESHOLD (1000) variables × parameters on, the crossover measured on chains with an added neural-network-like layer.

    The Native integrator runs the forward and the backward solve and the parameter quadrature in compiled code (Radau or LSODA, LLVM or wasm backend). It can't integrate forward sensitivities, so auto always uses the compiled adjoint with it. Models it can't compile fall back to the Python adjoint, and its CVODE methods to the variables × parameters rule.

    Here is a model with \(n = 6\) states and a layer of 20 tanh units feeding back into every state, 266 parameters in total:

    def layer(  # noqa: PLR0917
    x0: float,
    x1: float,
    x2: float,
    x3: float,
    x4: float,
    x5: float,
    w0: float,
    w1: float,
    w2: float,
    w3: float,
    w4: float,
    w5: float,
    b: float,
) -> float:
    return math.tanh(w0 * x0 + w1 * x1 + w2 * x2 + w3 * x3 + w4 * x4 + w5 * x5 + b)


def scaled(h: float, v: float) -> float:
    return v * h


def hybrid(n: int, n_hidden: int) -> Model:
    rng = np.random.default_rng(0)
    xs = [f"x{i}" for i in range(n)]
    model = Model().add_variables({x: 1.0 / (i + 1) for i, x in enumerate(xs)})
    for i, x in enumerate(xs):
        model.add_parameter(f"k{i}", 1.0 / (i + 1))
        stoichiometry = {x: -1} | ({xs[i + 1]: 1} if i + 1 < n else {})
        model.add_reaction(
            f"v{i}", fns.mass_action_1s, args=[x, f"k{i}"], stoichiometry=stoichiometry
        )
    for j in range(n_hidden):
        weights = {f"w{j}_{i}": float(rng.normal(0, 0.3)) for i in range(n)}
        model.add_parameters(weights | {f"b{j}": 0.0})
        model.add_derived(f"h{j}", layer, args=[*xs, *weights, f"b{j}"])
        for k, x in enumerate(xs):
            model.add_parameter(f"c{j}_{k}", float(rng.normal(0, 0.05)))
            model.add_reaction(
                f"r{j}_{k}", scaled, args=[f"h{j}", f"c{j}_{k}"], stoichiometry={x: 1}
            )
    return model

    All three agree to the integration tolerance. The forward sensitivities' cost grows with the number of parameters, the adjoint's doesn't, and the compiled adjoint is about two orders of magnitude faster still. For a few parameters (here: \(n \cdot m < 1000\)) forward sensitivities are faster, which is why auto keeps them there.

    Limitations¶

    • Models with events use forward sensitivities (or finite differences); method="adjoint" raises.
    • Fits with a postprocess_fn use finite differences of the runner's results.
    • Models that can't be differentiated symbolically (e.g. neural-network surrogates) fall back to forward sensitivities, and from there to finite differences.
