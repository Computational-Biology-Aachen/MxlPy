    Bayesian inference (MCMC)¶

    A fit returns the single parameter set that best describes the data. It doesn't tell you how well the data constrain each parameter: often a whole range of values fits almost equally well.

    mxlpy can instead sample the posterior distribution of the parameters given the data, using Markov chain Monte Carlo (MCMC). From the samples you get credible intervals, correlations between parameters and the uncertainty of predictions.

    The posterior combines two ingredients:

    • the likelihood of the data: the data are assumed to be the model's prediction plus Gaussian measurement noise with a known standard deviation sigma
    • a prior per sampled parameter: what you know about the parameter before seeing the data, given as a distribution from mxlpy.distributions

    Creating synthetic data¶

    As in the fitting tutorial, we create noisy synthetic data from a model with known parameters.

    Sampling the posterior¶

    fit.mcmc_time_course takes the data, a prior for every parameter to sample and the noise level sigma. The keys of prior are the sampled parameters; all other parameters keep their model values.

    Rate constants are positive and can span orders of magnitude, so a log-normal prior is a natural choice. Parameters whose prior lives on (0, inf) are sampled as their logarithm internally, which makes the sampler much more efficient; all results are reported in natural units.

    Several independent chains run in parallel. A seed makes the samples reproducible.

    Checking convergence¶

    Before interpreting the samples, check that the chains have converged to the same distribution.

    • R-hat compares the chains with each other; values below about 1.01 indicate convergence
    • the effective sample size (ESS) estimates how many independent samples the correlated chain samples are worth; a few hundred are enough for intervals
    • the acceptance rate of the sampler should be roughly between 0.15 and 0.5

    Steady states and protocols¶

    The steady-state and protocol variants work the same way. sigma can also be given per data column (or entry, for steady states) as a pandas.Series, or per data point as a pandas.DataFrame. Missing data (NaN) are ignored.

    Here the steady state only constrains the ratios of the rate constants, so we fix k1 and only sample the others.

    Advanced topics / customisation¶

    Priors¶

    Any distribution with a log_pdf and a positive_support (the mxlpy.distributions.Prior protocol) can be a prior, e.g. a Normal for a parameter that can be negative (it is then sampled linearly), or a Uniform for hard bounds.

    Starting point¶

    By default the chains start (slightly spread out) at the model's current parameter values. Starting from a previous fit with x0 saves warm-up time.

    minimizer=fit.LocalScipyMinimizer(),
).unwrap_or_err()

res = fit.mcmc_time_course(
    model_fn(),
    data=data,
    prior={k: LogNormal(0, 1) for k in best.best_pars},

    n_samples=500,
    seed=0,
).unwrap_or_err()

    Sampler¶

    The default sampler is fit.AdaptiveMetropolis (Haario et al. 2001): during a warm-up it adapts the covariance of its Gaussian proposals to the shape of the posterior, then it samples with the proposal frozen. The warm-up is discarded and defaults to as many steps as samples.

    Any callable following the fit.McmcSampler protocol can be passed as sampler.

    In [15]:
