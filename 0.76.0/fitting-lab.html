    Fitting lab¶

    Fitting an ODE model well takes more than calling a minimizer: which parameters can the data determine, did the optimizer find the best fit, are the residuals noise or missing dynamics, how certain are the estimates and predictions? mxlpy.lab takes one model and one or several data sets through these questions as a guided pipeline:

    Step Method What it does
    0 step0_setup maps data columns to model outputs (with scale/offset observables), estimates the measurement noise, picks an integrator and times the model
    1 step1_select_parameters ranks parameters by their sensitivities, drops collinear ones, limits their number by the sensitivity rank and the time budget
    2 step2_fit multi-start fits with a χ² goodness-of-fit test, multi-start convergence and residual whiteness; with several data sets condition-specific parameters
    3 step3_diagnose only if step 2 fails: hidden states until the residuals are white, then structural variants of the flagged variables
    4 step4_identifiability Fisher information, pulling test and profile likelihoods, proposes parameters to fix
    5 step5_uncertainty prediction bands of the observables (and optionally a posterior)

    Every step ends at a review gate with its result and a proposal. Calling the next step accepts the proposal, decide overrides it, and run(auto=True) goes straight through. Steps are addressed by key ("fit"), number (2) or method name. All results are checkpointed in a run directory, so an interrupted run resumes where it stopped.

    Example: an inhibited pathway, measured in arbitrary units¶

    A substrate \(S\) is converted to \(P\) through an intermediate \(X\), and an inhibitor \(I\) slows the first step. Two experiments were done: a control and one with the inhibitor. \(S\) was measured in concentrations, \(P\) only relative to an unknown scale (e.g. a western blot), as the column P_au.

    def pathway() -> Model:
    return (
        Model()
        .add_parameters({"k1": 1.0, "k2": 0.5, "kd": 0.05, "Ki": 0.5, "I": 0.0})
        .add_variables({"S": 2.0, "X": 0.0, "P": 0.0})
        .add_derived("k1_eff", fns.div, args=["k1", "inhibition"])
        .add_derived("inhibition", fns.add, args=["one", "I_rel"])
        .add_parameter("one", 1.0)
        .add_derived("I_rel", fns.div, args=["I", "Ki"])
        .add_reaction("v1", fns.mass_action_1s, args=["S", "k1_eff"], stoichiometry={"S": -1, "X": 1})
        .add_reaction("v2", fns.mass_action_1s, args=["X", "k2"], stoichiometry={"X": -1, "P": 1})
        .add_reaction("v3", fns.mass_action_1s, args=["P", "kd"], stoichiometry={"P": -1})
    )


def measure(inhibitor: float, seed: int):
    model = pathway().update_parameter("I", inhibitor)
    t = np.linspace(0.5, 15, 20)
    res = Simulator(model).simulate_time_course(t).get_result().unwrap_or_err()
    data = res.variables.loc[t, ["S", "P"]].rename(columns={"P": "P_au"})
    data["P_au"] *= 40.0  # unknown scale of the measurement
    rng = np.random.default_rng(seed)
    return data + rng.normal(0, [0.03, 1.0], data.shape)

    Each data set is a fit.Condition: its data plus what is special about the experiment, here the inhibitor concentration.     Step 0: setup¶

    The noise of every observable is estimated from replicates (repeated time points) or, as here, from pseudo-residuals of neighbouring points (each point against the cubic through its neighbours), pooled over the data sets measuring the same column. The scale of P_au starts at the ratio of the data's and the simulation's magnitude.

    Step 1: parameter selection¶

    At samples around the nominal values, the residual sensitivities of every candidate are computed (noise-weighted, w.r.t. log parameters). Parameters are ranked by their mean sensitivity and added greedily unless their sensitivity vector is nearly collinear with those already chosen (collinearity, the minimal sine of the angle). The number of parameters is limited by the rank of the sensitivities, the time budget (runtimes of the remaining steps are estimated per choice) and max_parameters.

    Step 2: fit¶

    Multi-start least-squares fits in log space. The fit passes if the χ² goodness-of-fit test doesn't reject it and the residuals of every observable look white (runs and Ljung-Box tests, Bonferroni-corrected). The fraction of starts reaching the best objective tells whether the problem is hard to optimise. Calling step2_fit accepts the proposal of step 1; run.decide("parameters", parameters=[...]) would have chosen others.

    Step 4: identifiability¶

    Step 3 is skipped, as the fit passed. The identifiability analysis escalates from the Fisher information (cheap, local) over the pulling test to profile likelihoods with confidence intervals, all on all data sets jointly. Non-identifiable parameters come with the identifiable combination they are part of, and the proposal fixes the less sensitive ones and refits.

    Web UI¶
    With the lab extra (pip install "mxlpy[lab]"), a local web UI shows a run while it runs and lets you decide its gates in the browser:
    

    mxlpy lab serve runs/pathway        # prints http://127.0.0.1:8765/?token=...

    

    server = run.serve()                # the same from Python (also in notebooks)
server.stop()

    

    The server runs the steps in the background with run.run(wait=True): it stops at every gate until it is decided, in the browser or from Python with run.decide(...).
Each step page shows the step's results (data with the fit, multi-start waterfall, parameter sensitivities, profiles, prediction bands, hidden-state corrections) and its gate, a form built from the step's options (lab.Option), which decide checks values against.
While a step runs, the UI shows its loss traces, finished starts, the ETA and, for fits, the best fit so far.
Pause (or run.pause()) stops the run once the running step has finished; Resume (run.unpause()) continues it, and Report downloads report.html.
    

    The run directory stays the source of truth, so the browser is never required: mxlpy lab serve --watch only watches and decides while another process runs the steps (a run.lock lets only one process run them at a time), and mxlpy lab status prints the steps and gates.
The server listens on localhost only and needs the token from the printed address. On a cluster node, forward the port with ssh -L 8765:localhost:8765 node and open the printed address locally.
    

    Missing dynamics¶
    If the fit fails, step 3 trains hidden states (add_hidden_states, see augmented ODEs) with 1, 2, ... states until the residuals turn white, and shows where the mechanism is off.
Then it compares structural variants with select.compare: user-given variants={"name": fn(model) -> model} and generic edits of the flagged variables (an extra degradation, an unknown spline input and a delay of the production through a linear chain).
